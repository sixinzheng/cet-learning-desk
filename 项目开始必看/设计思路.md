## ⭐ 项目两大核心特色（最高优先级）

### 1. 段位系统
科举十级晋升是项目的灵魂。每一个功能模块都为段位系统贡献数据。用户打开软件第一眼就看到自己的段位、进度、升段条件。这是激励用户持续学习的核心机制。

### 2. 可视化学习
学习不是枯燥的背诵，而是可视化的成长过程。每一天的学习都要转化为可见的成果：热力图、雷达图、进度环、星级评定、环形图。用户能看到自己"今天比昨天进步了多少"。

> 这两条高于一切 UI 美化需求。功能设计必须围绕这两条展开。

## 二、设计审美（当前 token 契约，**勿改色值**）

> `tests/test_site_contract.py` 断言了以下 token 与布局约束，改动会导致测试失败。纸墨/靛青/朱红体系，明亮温馨。

- **底色**：`--paper #f5f0e7` / `--paper-deep #e9e1d4` / `--surface #fffaf1` / `--surface-strong #ffffff`
- **主色（靛青）**：`--indigo #303b67` / `--indigo-deep #252d52` / `--indigo-soft #e6e7ef`
- **点缀（朱红）**：`--vermilion #c4553e` / `--vermilion-deep #a84231` / `--vermilion-soft #f5e1da`
- **文字**：`--ink #25283a` / `--ink-2 #565564` / `--ink-3 #777482`
- **边框/状态**：`--border #d6cbbd` / `--border-strong #b9ad9f` / `--danger #a83f36` / `--warning #9a6429` / `--success #465b76`
- **字体**：英文 Georgia 衬线、中文微软雅黑；正文 14px+，指标 32px，单词 42px
- **铁律**：无 emoji（用 SVG 或纯文字）、无毛玻璃、无暗色模式、同色系统一、扁平干净
- **布局**：全屏宽度仪表盘（不要竖屏窄条）、高信息密度（不要大面积留白）
- **活跃列表项 idiom**：`box-shadow: inset 3px 0 0 var(--vermilion)`（站点级约定，全站统一，勿改样式）

## 四、背单词机制（五态艾宾浩斯 + 四档反馈，2026-08-16 版）

### 状态流
陌生 → 模糊 → 巩固 → 掌握 → 熟记（自动毕业出队）。`ebbinghaus_stage` = 当前状态内阶段序号。

### 学习页（`/study`）
- 语境选释义（4 选 1）→ 学习卡片 → 全部过关后统一拼写验证
- **连对 3 次 = 一词过关**；答错归零
- **当日即时复现**：答错/标模糊的词重插入队列当前位 +4~5 处（线性队列，非旧版指针退 2）
- 过关后批次反馈页：本批词 + 释义 + 例句 + 本批答错标记
- 键盘：1-4 答题 / 空格或回车继续；每词可手动移入熟记（斩）

### 复习页（`/review`）
- **四个模式独立判定**：闪卡 F / 选择 C / 听力 L / 看义打词 S
  - 闪卡：看词→回忆释义→翻转；**四档反馈：认识 / 模糊 / 忘记 / 熟记**
  - 选择：看含目标词的句子→选正确释义
  - 听力：听发音→选单词
  - 看义打词：看释义+挖空例句→拼写（产出式，复用 `spelling-check`，`mode='review'` 不重复计新词）
- **任意 2 个模式各连对 3 次 = 该词复习完成**，移出队列
- **四档反馈语义**（`services/review_service.py` `record_review`）：
  - `认识 recognize` → 答对路径（连对 +1、清连错）
  - `模糊 vague` → **软过关**（连对 +1、不打断连错），标当日模糊 `vague_flagged`；完成推进时**原地巩固**（下次间隔取当前 stage 间隔、不推进）
  - `忘记 forget` → 答错路径；**首错 `next_review=今天`（错词必复现）**，连错 2 次降级（模糊重置第1天 / 巩固回模糊 / 掌握回巩固）
  - `熟记 mastered` → 直接毕业（`status=熟记, stage=99, next_review=NULL` 彻底出队）
- **当日即时复现**（纯前端队列）：本轮标「模糊」→ 插到 `idx+4`；答「忘记」→ 插到 `idx+2`；不影响完成判定（软过关仍计入连对）
- **分档间隔**（按 `words.frequency`，`_intervals_for`）：
  - 高频（freq 4~5）快线：模糊 `[1,2,4,7,15]` → 巩固 `[30,60,90]` → 掌握 `[180]`
  - 低频（freq 1~3）慢线：模糊 `[2,4,8,15,30]` → 巩固 `[60,120,180]` → 掌握 `[365]`
- 闪卡四键按钮下方显示**预期间隔**（`GET /api/study/review-preview`，纯计算不写库）
- 复习完成 → 批次反馈页（完成词 + 本轮遗忘词）
- 键盘：空格翻面 / 1-4 评级或答题 / 回车校验拼写 / 空格继续
- 每词每天**最多推进 1 格**（`advance_word` 幂等），**到期必抽**（取消概率抽样）

### 数据追踪
- 学习：`user_words.consecutive_correct` 连对计数（连对 3 过关）
- 复习：前端 `wordMode[word_id]` 四模式计数 `{flashcard, choice, listening, spelling}`
- 模糊标记：`user_words.vague_flagged`（跨日自动清理，仅当日一轮内有效）

## 五、交互习惯

- 学习连对 3 次 = 通过；复习任意 2 模式各连对 3 = 完成
- 全部通过后统一拼写验证
- 点击左列表 → 弹窗查看单词，不跳转题目
- 正确选项 = 全部释义拼接（；分隔）
- 学习卡片必须显示题目例句翻译
- 键盘优先：数字键选答案、空格翻面/继续、回车校验

## 六、开发经验 & 教训

### CSS/UI
1. emoji 在 Windows GBK 终端输出会崩 → print 用纯 ASCII
2. SVG `<line>` 不支持 `d` 属性 → 用 `<path>` 画曲线
3. 微笑控制点方向：SVG y 轴向下，笑=两端 y 小中间 y 大（U 形），哭=反
4. Flask 模板不自动重载 → 需 `TEMPLATES_AUTO_RELOAD=True`
5. 重复 CSS 类定义 → 多次修改后注意清理
6. Alpine.js 的 x-show 和 async 函数 → 先切 loading 态等 50ms 再加载
7. AudioContext 复用 → 单例模式避免浏览器限制
8. **静态资源缓存**：`app.js` 注册 Jinja 全局 `asset(filename)`（按 mtime 出 `?v=`），改 JS/CSS 后刷新即拿新版，勿再手写 `?v=N`
9. **设计 hook 会自动扫描**：AI 改布局时，非站点既有元素会被标记（如左侧色条曾用 `border-left` 被拦，改回站点 idiom `box-shadow: inset 3px 0 0 var(--vermilion)`）

### JS 逻辑
10. `api()` 函数需先加载 `app.js`
11. async loadWord 时 phase 先切 loading 防闪烁
12. 选项 fallback 要放在 try/catch 外面
13. 状态 API 需同步设置 next_review 日期
14. **复习/学习页键盘监听**挂在 `window` 全局（`_keyBound` 防重复绑定），输入框聚焦时跳过；闪卡 div 勿再绑自身 keydown（会与全局双重触发）
15. 队列重插（当日即时复现）用 `splice + 目标位插入`，删除/重插后记得清 `wordFlags`

### 后端/工程
16. **DB 位置**：`data/vocab.db`（不是 `instance/vocab.db`）
17. **5400 端口旧进程坑**：werkzeug 在 Windows `SO_REUSEADDR` 下可双进程绑定同一端口，请求落到旧进程导致新增路由 404 → 排查 `netstat -ano | grep :5400`，见多 PID 就 `taskkill` 后干净重启
18. 测试须 `PYTHONPATH=. python tests/<文件>.py`（unittest，未装 pytest；tests/ 无 `__init__.py`）
19. 非 git 仓库 → 改前先备份到 `.backup-YYYY-MM-DD-*/`

## 七、技术原则

- 所有 AI 结果缓存到 SQLite
- DeepSeek API 月费控制在 ¥5 以内
- 单机本地运行，不上传用户数据
- 预留多用户扩展接口
- 离线降级：核心功能不依赖网络
- **每次进行页面布局修改前**，必须调用已安装的前端设计/UI-UX 风格 skill（`ui-ux-pro-max`），认真设计、列出清单后再动手写代码
- 设计 token 是被测试断言的**契约**：改色值/布局铁律前先跑 `test_site_contract.py`
